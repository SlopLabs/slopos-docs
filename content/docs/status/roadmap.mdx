As of 2026-11-11, SlopOS commit `b8b2855b`.

This page lists the work that is planned next and the larger plans that have
landed since August 2026. Today one plan is open, about CI; the rest of the
open work is defects, listed on [Known
limitations](/docs/status/known-limitations).

## How the source tree keeps its plans

The source repository keeps its plans in `plans/`, and a plan only ever
describes what is still to do. When part of it lands, that part is removed
from the plan, and how it works is described from then on in the source tree
and on the page for the subsystem here. When nothing is left, the plan is
deleted; git history keeps the record. So a feature that appears only in a
plan does not exist yet.

Beside its `README.md`, which states those rules, `plans/` now holds two
files: `ci-latency.md`, the one open plan, and `KNOWN_ISSUES.md`, working
notes on open defects. Plans can mention file paths that have since moved, so
check a path against the tree before relying on it.

## Faster continuous integration

**What it is for:** keeping the time from a push to a test result short, and
the runner minutes every push costs low. (`plans/ci-latency.md`)

**Where it stands:** CI runs four jobs side by side. Each is one shared setup
step followed by a `just ci-*` recipe, so a job that fails reproduces on
your machine with the command it ran, and `just ci` runs every lane in CI's
order. The gates job runs formatting, the host tests, clippy, the dev kernel
with every framekernel gate, the offline build, the release kernel with its
gates and the candidate compiler backend and linker. The suite job builds
the tests system, boots the suite once, grades that boot's capture (the test
list, the lock-order and CPU-placement gates), checks its disk image, then
runs the persistence, unclean-shutdown, USB and self-hosting-root boots.
The toolchain job checks the LLVM and Rust ports, and the last job runs Miri
and Verus. A check joins the job that already has its inputs, because
another machine costs a setup and a build to save a short boot. Compiler
output is cached by content, never by timestamp, and only on build steps: a
gate that asks what a compiler does gets no cache, since a cached answer
would prove nothing. The suite job is the longest. Still to do:

1. Find where the slowest userland tests wait. Eleven of them take most of
   the suite's test time, and none of that time is the kernel's: they wait
   on a consent or password timeout, a drain or a backoff.
2. Stop every job paying its own toolchain install, with a runner image that
   has it built in.

## What is not planned

Nothing in the tree plans these, so they are not coming soon:

- **More hardware.** Machines other than the tested laptop, and drivers for
  Wi-Fi, Bluetooth, audio and SATA ([Hardware](/docs/status/hardware-requirements)).
- **A compiler that rebuilds itself inside SlopOS.** The self-hosting plan
  considered it and left it uncommitted: it needs Python in the guest, tens
  of gigabytes and hours of CPU per build. The plan was retired with the
  compilers still cross-built on the host
  ([Toolchain](/docs/self-hosting/toolchain)).
- **IPv6, other filesystems, time zones.** See [Known
  limitations](/docs/status/known-limitations).
