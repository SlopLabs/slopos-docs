As of 2026-10-29, SlopOS commit `fa0f8f79`.

This page lists the work that is planned next and the larger plans that have
landed since August 2026. Today one plan is open, about CI; the rest of the
open work is defects, listed on [Known
limitations](/docs/status/known-limitations).

## How the source tree keeps its plans

The source repository keeps its plans in `plans/`, and a plan only ever
describes what is still to do. When part of it lands, that part is removed
from the plan, and how it works is described from then on in the source tree
and on the page for the subsystem here. When nothing is left, the plan is
deleted; git history keeps the record. So a feature that appears only in a
plan does not exist yet.

Beside its `README.md`, which states those rules, `plans/` now holds two
files: `ci-latency.md`, the one open plan, and `KNOWN_ISSUES.md`, working
notes on open defects. Plans can mention file
paths that have since moved, so check a path against the tree before relying
on it.

## Faster continuous integration

**What it is for:** keeping the time from a push to a test result short, and
the runner minutes every push costs low. (`plans/ci-latency.md`)

**Where it stands:** CI runs four jobs side by side, each a chain of steps
over one set of inputs, each meant to finish near the boot lane: the boot
lane itself (the tests build, the boot, the checks that read its log, and the
persistence, crash, USB and self-hosting-root boots), the gates (host tests,
kernels, the framekernel gates and the offline build), the toolchain (the C++
runtime, the LLVM port and the cross-build checks), and the proofs (Miri and
Verus). Compiler output is cached by content, never by timestamp. The gates
job is the longest today, because its builds run without the cache. Still to
do:

1. Split the gates recipe so its expansion builds can use the compiler cache
   and its compiler probes cannot (a cached answer from a probe would prove
   nothing), which takes the gates job below the boot lane.
2. Stop every job paying its own toolchain install, with a runner image that
   has it built in.

The boot is deliberately one run, because the ratchets grade one boot's
counts; making its slowest tests cheaper is a test change, not a CI change.

## What is not planned

Nothing in the tree plans these, so they are not coming soon:

- **More hardware.** Machines other than the tested laptop, and drivers for
  Wi-Fi, Bluetooth, audio and SATA ([Hardware](/docs/status/hardware-requirements)).
- **A compiler that rebuilds itself inside SlopOS.** The self-hosting plan
  considered it and left it uncommitted: it needs Python in the guest, tens
  of gigabytes and hours of CPU per build. The plan was retired with the compilers still
  cross-built on the host ([Toolchain](/docs/self-hosting/toolchain)).
- **IPv6, other filesystems, time zones.** See [Known
  limitations](/docs/status/known-limitations).
