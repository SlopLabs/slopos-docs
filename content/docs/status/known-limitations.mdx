---
title: "Known limitations"
description: "What SlopOS does not do yet, and which of those gaps are recorded as defects to fix."
---

As of 2026-10-29, SlopOS commit `fa0f8f79`.

SlopOS is a research system. Everything is tested in QEMU, and one laptop has
run an installed system. This page lists what is missing, what each gap means for
you, and its status:

- **Open defect**: a bug recorded in the source tree's `plans/KNOWN_ISSUES.md`,
  which says where in the code it lives. It is meant to be fixed, but no fix is
  scheduled.
- **No plan**: a gap nothing in the tree plans to close.

The [Roadmap](/docs/status/roadmap) says which plans are open; today the only
one is about CI.

## Hardware

- **Only one real machine has been tried.** Other PCs may boot, but nothing
  outside QEMU and the tested laptop has been run, and the laptop's recorded
  results are from 2026-10-03 to 2026-10-11, so much of what changed since
  then has been tried in QEMU only. See
  [Hardware](/docs/status/hardware-requirements).
  No plan.
- **Few device drivers.** Besides QEMU's virtio devices, SlopOS drives NVMe
  disks, USB sticks, the Realtek RTL8168h and RTL8168M wired cards, USB
  Ethernet adapters, Intel integrated graphics of the Tiger Lake, Alder Lake
  and Raptor Lake families, and USB, PS/2 and I²C-HID input. There is no
  driver for SATA disks, Wi-Fi, Bluetooth or audio, no GPU acceleration and
  no suspend. No plan.
- **USB through xHCI only, and three kinds of device.** Older USB controllers
  have no driver, and only keyboards and pointers, Bulk-Only storage and
  CDC Ethernet adapters bind; anything else is enumerated and left alone
  ([USB](/docs/architecture/usb)). No plan.
- **USB and keyboard rough edges.** An unresponsive xHCI controller holds the
  boot for up to 11 seconds, each of up to eight; a device that keeps
  reconnecting logs every attach and detach; a keyboard pulled out while
  another still holds Shift sends programs a Shift release, though Shift
  stays held; and on a machine with no xHCI controller, a keyboard-light
  update the PS/2 controller leaves unanswered is sent again only at the next
  key or lock change. Open defect.
- **PCI devices are found once, at boot.** A USB device can come and go, but a
  PCI card is probed only while the kernel boots, and drivers cannot be
  unloaded ([Drivers](/docs/architecture/drivers)). No plan.
- **The CPU's power limit is not read.** The kernel reads no RAPL register, so
  a build held back by the package's power limit shows only as the throttle
  bit in `cpufreq run` ([CPU frequency](/docs/architecture/cpu-frequency)).
  No plan.

## Kernel

- **Partial system call coverage.** System calls use Linux's numbers, but many
  are missing; a program that calls one gets `ENOSYS`. Coverage grows when a
  port needs it ([System calls](/docs/architecture/syscalls)). No plan as a
  goal in itself.
- **SlopRing covers less than io_uring.** It borrows the idea but does not aim
  to match Linux's feature set ([SlopRing](/docs/abi/slopring)). No plan.
- **Proofs cover selected logic only.** Machine-checked proofs cover the
  logic of selected parts of the trusted core, of SlopRing and of zero-copy
  TCP. The rest of the trusted core, and the memory ordering of the lock-free
  code even in those parts, is reviewed by hand and tested under Miri instead
  ([Proofs](/docs/verification/verus-status)). Proving the whole core is not
  a goal.
- **No kernel page-table isolation.** The kernel stays mapped (but
  inaccessible) while programs run, and relies on the processor's protection
  bits rather than unmapping itself, which is the defence Linux added against
  Meltdown ([User mode and kernel mode](/docs/architecture/privilege-separation)).
  No plan.
- **Safe kernel code can write the processor's control registers.** The
  trusted core exports `write_cr0`, `write_cr3`, `write_cr4` and `write_msr`
  as safe functions taking a raw value, and `write_msr` any register number,
  so a safe crate can load any page-table root or move the system-call entry
  point ([The framekernel](/docs/verification/framekernel)). Not yet recorded
  in `plans/KNOWN_ISSUES.md`.
- **A program's divide error stops the machine.** An integer division by zero
  or a stack fault in user mode is handled as a kernel error and panics the
  whole machine, where it should end only the program
  ([User mode and kernel mode](/docs/architecture/privilege-separation)). So
  any program can stop the computer. Not yet recorded in
  `plans/KNOWN_ISSUES.md`.
- **Interface edge cases.** `stat` reports the same device number for every
  file, so a program cannot tell two filesystems apart by it; a pidfd turns
  readable when the process's main thread exits even if other threads still
  run; and a thread that survives another's `execve` runs on in the new
  program. Open defect.

## Memory and scheduling

- **A link larger than an eighth of memory fails.** A page of a file a process
  has mapped stays pinned until it is unmapped, and one process may pin at most
  an eighth of memory, so a linker mapping more than that dies on a refused
  fault, and the filesystem it was writing turns read-only. The debug tests
  kernel's link does so in a 4 GiB guest, which is why the development machine and the
  self-hosting checks run at 6 GiB ([Memory](/docs/architecture/memory)). Open
  defect.
- **An idle CPU's page zeroing can fault.** Under heavy host load an idle CPU
  can take an invalid frame from its per-CPU cache and fault while zeroing it.
  The cause is not found, and no path a program drives is known to reach it.
  Open defect.
- **Some scheduler waits cost latency.** An idle CPU can briefly spin waiting
  for another to finish switching a task out, ending a task caught moving
  between two CPUs' queues takes every CPU's queue lock in turn, and during
  boot the scheduler is turned off for every CPU while the other CPUs already
  run programs. None of these is a correctness problem
  ([Scheduling and waiting](/docs/architecture/scheduler-wait-protocol)).
  Open defect.

## Storage

- **Only the ext4 features SlopOS knows.** SlopOS formats every volume with
  one set of ext4 features, and also mounts ext2, ext3 and ext4 volumes other
  systems made. But a volume using a feature it does not implement, such as
  inline data, encryption or case-insensitive names, is refused; one using a
  feature it can read but not write, such as `bigalloc`, mounts read-only;
  and a volume past 16 TiB at 4 KiB blocks is refused
  ([Filesystem](/docs/architecture/filesystem)). No plan.
- **No other filesystems.** A FAT or exFAT stick, btrfs, XFS or NTFS does not
  mount. The boot partition is FAT32, but only SlopOS's own tools write it,
  through the raw disk. No plan.
- **Four ext4 volumes at once.** The kernel mounts at most four ext4 volumes,
  the root and an install medium's payload among them; an extension's image
  does not count. No plan.

## Network

- **IPv4 only.** There is no IPv6. No plan.
- **Not hardened for the open Internet.** The stack carries real TCP, UDP, DNS
  and TLS 1.3 traffic, but it is a small stack and has not been through what an
  Internet-facing one has ([Networking](/docs/architecture/networking)). No
  plan.
- **No incoming remote login.** OpenSSH's `ssh` comes with the toolchain, but
  nothing runs its server. A machine is driven remotely only through the
  paired agent, which dials out to your host
  ([Remote control](/docs/self-hosting/remote-control)). No plan.

## Installing and updating

- **An install from a 512 MiB live system fails.** Booted the way
  `just boot-live` boots it, with 512 MiB of memory, the installer reaches the
  step that writes both kernel slots and the base and dies there (`SIGABRT`,
  right after the kernel logs `process_vm_mmap: Failed to insert VMA`).
  Whether more memory avoids it is not known; `just ui-shots` and
  `just test-installer` install at 2 GiB and 6 GiB
  ([Installing SlopOS](/docs/self-hosting/installing)). Open defect.
- **A new base gets no trial boot.** A kernel goes into the spare slot and is
  tried once before it becomes the default, but a base that passes its checks
  becomes current for every slot at once, and stays current when it then fails
  in userland until you roll it back (from the install medium's rescue shell
  when the system no longer gives you one) or a reinstall writes the medium's ([Updating SlopOS](/docs/self-hosting/updating)).
  Open defect.
- **Another loader can move SlopOS's default.** Which slot boots by default is
  a firmware variable every loader on the machine can write. Another system's
  loader that deletes it makes Limine boot its first entry, and one that sets
  it to a name Limine does not offer makes `bootctl install` refuse until
  `bootctl set-default` names a slot. Registering SlopOS's firmware entry can
  also add a second one, when the first sits outside the firmware's boot
  order at a number past the first free one.
  Open defect.
- **Installing for everyone through privd is bounded.** A tree installed into
  `/usr/local` for everyone is copied before it is installed, both counting
  against one disk quota, so it can be at most half of that quota; and it must
  be readable by everyone, so it cannot come from inside a home directory
  closed to others ([Installed software](/docs/architecture/software)). Open
  defect.

## Desktop and people

- **The clock shows UTC.** There are no time zones. No plan.
- **A person without a password can approve nothing at a text console.**
  There the question is always answered with the person's own password, so
  an action that asks, even for a click, is refused until they set one, which
  they can do from a terminal on their desktop
  ([Privileged actions](/docs/architecture/privd)). No plan.
- **A typed password lingers in memory.** A password typed into a dialog or
  relayed to a program stays in kernel pipe buffers and the compositor's
  memory until they are reused; no other program can read it there
  ([Privileged actions](/docs/architecture/privd)). Open defect.
- **Console input after a signal key is lost.** On the text console and the
  serial line, characters typed in the same burst after one that sends a
  signal, such as Ctrl+C, are dropped. Open defect.

## Toolchain

- **The compilers are built on the host.** LLVM and rustc are cross-built with
  `just toolchain`; SlopOS does not rebuild its own compiler, and no plan
  covers it ([Toolchain](/docs/self-hosting/toolchain)).
- **Not a tier 2 Rust target.** Rust ships no prebuilt standard library for
  SlopOS, so every build compiles it from source with `-Zbuild-std`. No plan.

## Where the full list lives

`plans/KNOWN_ISSUES.md` in the source tree holds every open defect, with the
files involved, including the low-severity ones this page leaves out:

- extension handling: what an activation costs in memory and boot time, a
  service that cannot listen because an extension init cannot read holds its
  port, and a trusted key whose ceilings are too long for the session to add;
- privd's requesters: a request read as privd begins to drain, signals
  passed on twice, input and signals that reach a mechanism out of order, and
  a remote command that outlives its timeout;
- a base switch that lands while init re-executes itself and goes unacted on;
- one lock taken on every lookup of a base file;
- a compositor client whose message wakes nothing until it sends again;
- `recvmsg` on a Unix socket taking every queued descriptor at once;
- peer identities that outlive what they describe;
- the rest of the kernel interface edge cases: a spawn request whose layout
  carries no size, a ring's connect whose permission check and recorded
  identity are taken at different moments, and descriptors `socketpair` and
  `accept` install before writing out their numbers, which a racing `dup2`
  can see;
- a short window at kernel thread start in which a test could tear the thread
  down.

It is working notes: check what it says against the code before relying on
it.
