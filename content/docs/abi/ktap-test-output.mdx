title: "Test output format"
description: "What the kernel test harness prints on the serial console, and the JSON events and exit codes the host test runner produces from it."
---

When SlopOS boots with `tests=on`, the kernel test harness prints its results
on the serial console in KTAP, the Linux kernel's test output format. The host
runner (`tools/run_tests/`, built to `builddir/run_tests` and run by
`just test`) reads that stream, shows progress, and can write the results as
JSON lines. This page lists both formats and the runner's exit codes. The
emitter is the `ktesting` crate; the parser is `tools/run_tests/parser.go` and
the JSON writer `tools/run_tests/jsonl.go`. The options that control the
harness (`tests.run`, `tests.verbosity` and the rest) are listed in
[Boot options](/docs/abi/boot-options#tests).

## Phases

| Phase | Tests registered with | Run by |
|---|---|---|
| 1, kernel | `stest!` | The kernel during boot |
| 2, userland | `utest!`, one userland program per test, and `stest!(..., kind = Userland)` | A copy of init (`/sbin/init --run-tests`) that asks the kernel to run them, so init keeps serving meanwhile |

Each phase prints its own header. The runner names phases by order: the first
`TAP version 14` header is the kernel phase, the second the userland phase.

## Line prefix

Every harness line starts with `KTAP` and a tab. Ordinary kernel log lines are
interleaved with them and the parser ignores those. Diagnostic and subtest
lines add two spaces after the tab.

## Header

```text
KTAP	TAP version 14
KTAP	1..N
```

`N` is the number of tests in the phase after `tests.run` and `tests.skip`
are applied. A test registered as explicit (`FLAG_EXPLICIT`, `utest!(...,
explicit)`) counts only when a `tests.run` pattern is its full name. A filter
that matches nothing gives `1..0`.

## Result lines

```text
KTAP	ok 17 - slopos_mm::tests::tests::test_heap_kmalloc_zeroed # time_ms=3
KTAP	ok 18 - slopos_mm::tests::tests::test_heap_large_alloc # time_ms=812 OVER_TIME
KTAP	ok 19 - slopos_net::tests::tcp_tests::test_tcp_parse_minimal_header # SKIP test returned Skipped
KTAP	not ok 42 - slopos_net::tests::tcp_tests::test_tcp_parse_too_short # time_ms=11
```

The name is the Rust module path of the registration and the test's name.
The text after `#` holds:

| Token | Meaning |
|---|---|
| `time_ms=N` | How long the test took |
| `NO_TIME_BASE` | In place of `time_ms` when no clock was available |
| `OVER_TIME` | Passed, but slower than `tests.warn_ms` |
| `EXPECTED_PANIC` | The test was registered as expecting a panic, and panicked |
| `SKIP <reason>` | Skipped; KTAP writes a skip as `ok`. A kernel test's reason is always `test returned Skipped` |

With `tests.verbosity=quiet` the harness prints only failing results, and
of the subtest lines below only the failing ones.

## Diagnostic block

A failing test is followed by a block in YAML style:

```text
KTAP	  ---
KTAP	  outcome: Fail
KTAP	  file: net/src/tests/tcp_tests.rs:1694
KTAP	  log: |
KTAP	   captured klog line
KTAP	   --- cpu2 ---
KTAP	   klog line captured on another CPU
KTAP	  ...
```

| Key | Meaning |
|---|---|
| `outcome` | `Fail` or `Panic` |
| `file` | Where the test is registered: the file and line of its `stest!` or `utest!`, not of the failure |
| `log` | Kernel log captured while the test ran: the harness CPU first, then a `--- cpuN ---` section for each other CPU that logged |

When the capture was cut short, the log contains `[head trimmed: N bytes]`
(a CPU logged more than the 4096 bytes the block prints for each) or
`[cpu0 tail trimmed: N bytes lost to ring overflow]` (the harness CPU's
capture buffer wrapped; the text says `cpu0` whichever CPU that is). With
`tests.verbosity=verbose` a passing test may print a block with only `log`.
A test registered with `FLAG_UNCAPTURED` has no captured log, so its block has
no `log` key and no closing `...` line.

## Subtests

A `utest!` program reports its individual cases with the `test_report` system
call. Once the program has exited, the kernel prints each case as an
indented line, before the test's own result line:

```text
KTAP	  ok 1 - alloc_dealloc_basic
KTAP	  ok 2 - forward_coalesce # 64 blocks merged
KTAP	  ok 3 - mmap_fallback # SKIP
KTAP	ok 5 - slopos_core::utests::utest_heap_allocator # time_ms=234
```

- The parser collects indented lines and attaches them to the next
  top-level result.
- On a passing case, text after `#` is a note; only `SKIP` changes the
  outcome. A failing case is `not ok N - name # message`, and any failing
  case fails the test, so its own result line is `not ok` too.
- Notes and messages are cut to their first line. The `test_report` call
  already cut a name at 64 bytes and a note or message at 128.
- A skipped case is `ok N - name # SKIP`, with no reason.
- The kernel keeps at most 192 cases for one test
  (`TEST_REPORT_RING_CAPACITY`). Past that it drops the rest and adds a
  failing case named `report_ring_overflow`.
- Subtest lines go straight to the console rather than through the per-test
  log capture, so a long test that overflows the capture cannot lose them.

## Footer, bail-out and abort

```text
KTAP	# elapsed_ms=14238 pass=2391 fail=1 skip=0 over_time=14
```

- Each phase ends with a footer holding its time and counters.
- If a test whose name starts with `bootstrap_` fails, the harness prints
  `KTAP	Bail out! <test name>` and runs no more tests in that phase.
- The format-free abort a lockup or a broken unwind takes prints
  `=== KERNEL ABORT ===` and a reason line, which the runner records as a
  kernel abort. The other CPUs may go on producing results, so the runner
  keeps reading. A fatal panic prints `=== KERNEL PANIC ===`, and the tests kernel then
  writes `1` to `isa-debug-exit`; the phase has fewer results than its plan,
  which the runner reports as output cut short.
- With `tests.shutdown=on`, the kernel then writes `0` (all passed) or `1`
  (something failed) to QEMU's `isa-debug-exit` device. QEMU exits with
  `(value << 1) | 1`, so the runner does not rely on that status alone: it also
  requires at least one phase header.

## Host runner

| Recipe | Runner flag | Effect |
|---|---|---|
| `just test FILTER` | `--filter GLOB` | Repeatable; joined with commas into `tests.run=` |
| | `--skip GLOB` | Repeatable; joined into `tests.skip=` |
| | `--warn-ms N` | `tests.warn_ms=N`; default `500` |
| `just test-rerun-failed` | `--rerun-failed` | Runs the failures recorded in `builddir/last-fail.list` |
| `just test-verbose` | `--verbose` | `tests.verbosity=verbose`; shows the captured log of every test |
| `just test-quiet` | `--quiet` | `tests.verbosity=quiet`; shows only failures and the summary |
| `just test-raw` | `--raw` | Prints QEMU's serial output unchanged |
| `just test-json PATH` | `--json PATH` | Writes one JSON event per line to `PATH`, replacing what it held |
| | `--timeout-secs N` | Stops the whole run after `N` seconds; default `900`, `0` disables |
| | `--silence-secs N` | Stops the run if QEMU prints nothing for `N` seconds; default `120`, `0` disables |
| | `--color auto\|always`, `--no-color` | Colour of the rendered output; `NO_COLOR` in the environment also turns it off unless `--color always` |
| | `--iso PATH`, `--fs-image PATH` | Boot this ISO and test image instead of `builddir/slop-tests.iso` and `fs/assets/ext4-tests.img` |
| | `--no-build` | Boots the existing ISO without running `just _iso-tests` first |
| | `--dry-run` | Prints the command line it would use and exits |

`--verbose`, `--quiet` and `--raw` exclude each other, and so do
`--rerun-failed` and `--filter`. `--raw` still parses the stream to decide the
exit code. The runner reads its starting command line from the justfile
(`just --evaluate test_cmdline`), currently
`tests=on tests.shutdown=on tests.verbosity=summary boot.debug=on roulette=skip root=auto mount=LABEL=slopos-media:/media`,
adds the options its flags select, and hands the result to `just _iso-tests`
as `TEST_CMDLINE`.

### Exit codes

| Code | Meaning |
|---|---|
| `0` | Tests ran and all passed |
| `1` | A test failed, a phase bailed out, the run timed out, the output was cut short, or the kernel aborted |
| `2` | No trustworthy answer: no phase header appeared, an unfiltered run planned zero tests, or QEMU's wrapper exited with an unexpected status |
| `64` | Bad command-line arguments (`--rerun-failed` with no recorded failures among them), or the runner could not build the ISO, find the ISO or test image, or start QEMU |
| `130` | Interrupted with Ctrl-C |

## JSON lines

`--json PATH` writes one JSON object per line. Every object has a `t` field
naming the event. Every field is always present; a missing value is `null`.

| `t` | Fields |
|---|---|
| `phase_start` | `idx`, `name` |
| `plan` | `phase_idx`, `n` |
| `test` | `phase`, `phase_idx`, `idx`, `name`, `outcome`, `time_ms`, `over_time`, `expected_panic`, `skip_reason`, `fail_file`, `fail_outcome_kind`, `log`, `pre_fail_klog_tail`, `subtests` |
| `phase_end` | `idx`, `name`, `elapsed_ms`, `pass`, `fail`, `skip`, `over_time` |
| `bail` | `phase_idx`, `reason` |
| `kernel_abort` | `reason` |
| `run_end` | `wall_ms`, `exit`, `qemu_status`, `user_aborted`, `timed_out`, `silence_hit`, `truncated`, `kernel_abort`, `kernel_abort_reason`, `phases` |

- `outcome` is one of `pass`, `fail`, `skip`, `bail`, `not_run`, `timeout`.
- Each entry in `subtests` has `idx`, `name`, `outcome` and `msg`.
- `fail_outcome_kind` is the diagnostic block's `outcome` (`Fail` or `Panic`).
- `pre_fail_klog_tail` holds recent console lines that were not KTAP, for a
  failure that carried no captured log.
- `run_end` is always the last event. Each entry in its `phases` array has
  `idx`, `name`, `plan_n`, `elapsed_ms`, `pass`, `fail`, `skip`, `over_time`
  and `bail` (the bail-out reason, or `null`).

```json
{"expected_panic":false,"fail_file":null,"fail_outcome_kind":null,"idx":17,"log":null,"name":"slopos_mm::tests::tests::test_heap_kmalloc_zeroed","outcome":"pass","over_time":false,"phase":"kernel","phase_idx":1,"pre_fail_klog_tail":null,"skip_reason":null,"subtests":[],"t":"test","time_ms":3}
```
