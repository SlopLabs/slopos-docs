This page lists the rules of the SlopOS system call interface: numbering,
registers, return values and the families of calls. The authoritative table of
numbers is `abi/src/syscall/numbers.rs` (crate `slopos_abi`); errno values are
in `abi/src/errno.rs`. [System calls](/docs/architecture/syscalls) explains how
the kernel handles a call.

## Numbering

| Range | Contents | Rule |
|---|---|---|
| `0` to `472` (`SYSCALL_LINUX_MAX`) | Linux-numbered calls | Number, name, arguments and behaviour are those of the Linux x86-64 call |
| `1024` (`SYSCALL_PRIVATE_BASE`) upwards | SlopOS-only calls | Numbered `1024 + k`, contiguous from `k = 0`; the private table holds 48 slots (`SYSCALL_PRIVATE_TABLE_SIZE`) |

- A number below 1024 always means the Linux call with that number. If SlopOS
  does not implement it, the number returns `-ENOSYS`; it is never reused for
  something else.
- 1024 is above every number Linux has assigned and below the x32 marker bit
  (bit 30), so a private number cannot be mistaken for either. ARM uses the same
  scheme with `__ARM_NR_BASE`.
- SlopRing uses private numbers, not io_uring's (425 to 427), because it does
  not implement io_uring's interface.
- `scripts/check_syscall_abi.sh` enforces these rules. It compares every
  number below 1024 with a vendored copy of Linux's `syscall_64.tbl` and
  fails if a name sits on a number Linux gave to another call, if the private
  range has a gap, if a number or name is used twice, or if a private name
  matches a Linux call without an allowlist entry explaining why.
- Numbers changed in September 2026 (a breaking change). Programs built
  against older numbers do not run on current kernels.

## Registers

The calling convention is the Linux x86-64 one.

| Register | Use |
|---|---|
| `rax` | System call number on entry, return value on exit |
| `rdi`, `rsi`, `rdx`, `r10`, `r8`, `r9` | Arguments 1 to 6 |
| `rcx`, `r11` | Overwritten by the `syscall` instruction |

The fourth argument is in `r10`, not `rcx`, because the `syscall` instruction
stores the return address in `rcx`.

## Return values and errors

- Success returns a value of zero or more.
- Failure returns a negated errno, so any value from `-4095` to `-1` is an
  error.
- Errno values use Linux's numbers (`EPERM` is 1, `ENOSYS` is 38).
- A number with no handler, in either range or outside both, returns
  `-ENOSYS`.
- `ERESTARTSYS` (512) and `ERESTARTNOHAND` (514) are kernel-internal and never
  reach a program. When a signal interrupts a call that returned one of them,
  the kernel either restarts the call after the signal handler runs or returns
  `-EINTR`, following Linux's `SA_RESTART` rules.

## Rules for changing the ABI

- `abi/src/syscall/numbers.rs` is the only place a number is written down.
  Userland imports the constant; documentation does not repeat numbers.
- A Linux-numbered slot holds only the Linux call of that number, with
  Linux's arguments.
- A new SlopOS-only call takes the next free `1024 + k`. When the private
  table is full, `SYSCALL_PRIVATE_TABLE_SIZE` grows.
- Every struct passed between a program and the kernel is `#[repr(C)]` and has
  compile-time checks on its size and field offsets.

[Add a syscall](/docs/development/adding-a-syscall) walks through adding one.
The Linux [`syscall(2)`](https://man7.org/linux/man-pages/man2/syscall.2.html)
and [`errno(3)`](https://man7.org/linux/man-pages/man3/errno.3.html) man pages
document the conventions SlopOS follows, and Linux's
[`syscall_64.tbl`](https://github.com/torvalds/linux/blob/master/arch/x86/entry/syscalls/syscall_64.tbl)
is the numbering it follows.
