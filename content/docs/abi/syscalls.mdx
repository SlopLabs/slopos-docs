This page lists the SlopOS system call interface: numbering, registers, return
values, the capability each call needs, and every registered call. The
authoritative sources are `abi/src/syscall/numbers.rs` (each number, with the
call's signature in its doc comment), `core/src/syscall/handlers.rs` (the two
dispatch tables) and each handler's `cap(...)` clause in `core/src/syscall/`.
Errno values are in `abi/src/errno.rs`, capability bits in `abi/src/caps.rs`.
The private calls below are those of base interface 12.
[System calls](/docs/architecture/syscalls) explains how the kernel handles a
call.

## Numbering

| Range | Contents | Rule |
|---|---|---|
| `0` to `472` (`SYSCALL_LINUX_MAX`) | Linux-numbered calls | Number, name, arguments and behaviour are those of the Linux x86-64 call |
| `1024` (`SYSCALL_PRIVATE_BASE`) to `1077` | SlopOS-only calls | Numbered `1024 + k`, contiguous from `k = 0`; the private table holds 54 slots (`SYSCALL_PRIVATE_TABLE_SIZE`) |

- A number below 1024 always means the Linux call with that number. If SlopOS
  does not implement it, the number returns `-ENOSYS`; it is never reused for
  something else.
- 1024 is above every number Linux has assigned and below the x32 marker bit
  (bit 30), so a private number cannot be mistaken for either. ARM uses the
  same scheme with `__ARM_NR_BASE`.
- A private call taken away keeps its slot, which answers `-ENOSYS`, so a base
  built before it still boots. Slot `1056` (`roulette_draw`) is such a slot.
- SlopRing uses private numbers, not io_uring's (425 to 427), because it does
  not implement io_uring's interface.
- `scripts/check_syscall_abi.sh` enforces these rules. It compares every
  number below 1024 with a vendored copy of Linux's `syscall_64.tbl`
  (`scripts/gates/syscall/linux-x86_64.tbl`) and fails if a name sits on a
  number Linux gave to another call, if the private range has a gap, if a
  number or name is used twice, or if a private name matches a Linux call
  without an entry in `scripts/gates/syscall/private-allowlist.txt`
  explaining why.

## Registers

The calling convention is the Linux x86-64 one.

| Register | Use |
|---|---|
| `rax` | System call number on entry, return value on exit |
| `rdi`, `rsi`, `rdx`, `r10`, `r8`, `r9` | Arguments 1 to 6 |
| `rcx`, `r11` | Overwritten by the `syscall` instruction |

The fourth argument is in `r10`, not `rcx`, because the `syscall` instruction
stores the return address in `rcx`.

## Return values and errors

- Success returns a value of zero or more.
- Failure returns a negated errno, so any value from `-4095` to `-1` is an
  error.
- Errno values use Linux's numbers (`EPERM` is 1, `ENOSYS` is 38).
- A number with no handler, in either range or outside both, returns
  `-ENOSYS`.
- A call whose capability the caller does not hold returns `-EPERM` before
  its handler runs.
- `ERESTARTSYS` (512) and `ERESTARTNOHAND` (514) are kernel-internal and never
  reach a program. When a signal interrupts a call that returned one of them,
  the kernel either restarts the call after the signal handler runs or returns
  `-EINTR`, following Linux's `SA_RESTART` rules. `nanosleep`, `poll`, `futex`
  and `ring_enter`, which carry a timeout they do not hand back, return
  `-EINTR` instead.

## Capability classes

Every call has one class, fixed at compile time in its handler's `cap(...)`
clause. The dispatcher compares it with the calling task's capability mask.
[Capabilities](/docs/architecture/authority) explains the mask, who holds what
and how a program is given a capability.

| Class | Who may make the call |
|---|---|
| `NoneSelf` | Anyone. The call acts on the caller, or reports what any process may know |
| `NoneFd` | Anyone. The call acts on what the caller names by descriptor or path; file permissions still apply to a path (see [Users and file permissions](/docs/architecture/users)) |
| `NoneRelation` | Anyone. The handler checks the caller's relation to the target itself (parent, session, the signal rule) |
| `ConsoleIo`, `ClipboardGlobal`, `Fate` | A holder of that capability. These three are universal: every program holds them unless it or its spawner dropped them |
| Any other capability (`Power`, `Mount`, `SysInspect`, ...) | A holder of that capability, which only a spawner that holds it can delegate |

Some calls check more inside the handler, through `SyscallContext::holds`:
the credential calls (`SetId`), `setpriority` (`SchedHigh`), `net_query`'s
socket owners (`NetAdmin`), and the display calls, which also require the
screen or input seat.

| Constant | Value | Meaning |
|---|---|---|
| `BASE_INTERFACE` | `12` | The interface this tree's private calls form |
| `BASE_INTERFACE_MIN` | `10` | The oldest interface a kernel built from this tree serves |

- A kernel states its range in `sys_info` and in the ELF note
  `.note.slopos.base-interface` (owner `SlopOS`, type
  `NT_SLOPOS_BASE_INTERFACE`, two `u32` values: minimum and maximum), which
  can be read from the file without booting it. A base states its number in
  `/usr/share/slopos/base-interface`.
- The interface covers every private call's number and signature, every
  `slopos_abi` item a signature names or a call's documentation links, what
  those items reach through their fields, and the families the `root` lines
  of `scripts/gates/base-interface.txt` name (capability bits, ring layouts,
  spawn attributes, network records, the kept directories, the extension
  name grammar and others).
- It does not cover the Linux-numbered calls or the Linux structures a private
  call passes through (`sockaddr`, `msghdr`, `iovec`), which follow Linux.
- `scripts/check_base_interface.sh` digests that surface from rustdoc's view
  of `slopos-abi` and holds it to the ledger row for `BASE_INTERFACE` in
  `scripts/gates/base-interface.txt`. A change to the surface takes the next
  number. The minimum rises only when a change reshapes something an older
  base calls; an addition leaves it, and so does a call retired to
  `-ENOSYS`.

A program outside the base never makes a private call. It reaches SlopOS
through `libc.so`, whose exported symbols and header structure layouts only
grow: `scripts/check_libc_exports.sh` holds them to
`scripts/gates/libc/exports.txt` and `scripts/gates/libc/layouts.txt`.

## Rules for changing the ABI

- `abi/src/syscall/numbers.rs` is where a number is defined, with the call's
  signature in its doc comment. Programs import the constant.
- A Linux-numbered slot holds only the Linux call of that number, with
  Linux's arguments.
- A new SlopOS-only call takes the next free `1024 + k`, and
  `SYSCALL_PRIVATE_TABLE_SIZE` grows to hold it. It takes the next base
  interface number.
- Every struct passed between a program and the kernel is `#[repr(C)]` and has
  compile-time checks on its size and field offsets.

[Add a syscall](/docs/development/adding-a-syscall) walks through adding one.
The Linux [`syscall(2)`](https://man7.org/linux/man-pages/man2/syscall.2.html)
and [`errno(3)`](https://man7.org/linux/man-pages/man3/errno.3.html) man pages
document the conventions SlopOS follows, and Linux's
[`syscall_64.tbl`](https://github.com/torvalds/linux/blob/master/arch/x86/entry/syscalls/syscall_64.tbl)
is the numbering it follows.
