---
title: "Glossary"
description: "The words SlopOS uses for its own ideas, what each means, and where it is explained."
---

The terms below are the ones SlopOS gives its own ideas, in the sense the
source tree uses them. Each entry says what the term means, what other
systems call the nearest thing where there is one, and which page explains
it. Words with their usual Unix meaning (process, file descriptor, inode,
mount) are not listed.

| Term | Meaning | Elsewhere | Explained in |
|---|---|---|---|
| Accounts record | The sealed store in `/var/lib/slopos/accounts` that lists the people: each one's uid, name, home, whether they administer the machine and their password's hash, and whom the desktop logs in by itself. `/etc/passwd`, `/etc/group` and `/etc/shadow` are written from it and from the packages' records | `/etc/passwd` and `/etc/shadow` on Linux | [Users and file permissions](/docs/architecture/users#the-accounts-record) |
| Action | A named thing privd will do on request, such as `org.slopos.power.reboot`: the program it runs, the arguments it accepts, the capabilities it gets and who may ask for it | A polkit action | [Privileged actions](/docs/architecture/privd), [privd actions](/docs/abi/privd-actions) |
| Activation | One package image shown read-only at `/opt/<name>`. Replacing it makes a new activation; the old one is freed once nothing uses it | A mounted system extension | [Packages](/docs/architecture/packages) |
| Adapter | A network card as `netctl` and Settings name it: by its hardware address, or by the kernel's interface name (`eth0`), which passes to the next card once its holder leaves | A NetworkManager device | [Networking](/docs/architecture/networking#settings-that-last-across-restarts) |
| Administrator | A person the accounts record marks as one, and so a member of the `admin` group. privd's `admin` principal names them; the kernel grants them nothing | A member of `wheel` or `sudo` | [Users and file permissions](/docs/architecture/users) |
| App | A program with a window, usually with an entry in the dock. The base carries a few (the terminal, the System Monitor, the installer window); the apps shipped outside it (editor, file manager, image viewer, Breach, and the widget gallery, which has no dock entry) are the image `slopos-essentials`, shown at `/opt/slopos-essentials` | Desktop application | [Desktop](/docs/architecture/desktop), [Installed software](/docs/architecture/software) |
| App entry | A `share/slopos/apps/<id>.app` file naming an app's id, name, program and icon, which the dock reads | A `.desktop` file | [Installed software](/docs/architecture/software) |
| appkit | SlopOS's toolkit: an app describes its window as a tree of components, and the components carry the spacing, type, colour, focus and keyboard behaviour | GTK with libadwaita | [Desktop](/docs/architecture/desktop#components) |
| At rest | A volume's state on the medium when nothing is owed to it: the journal empty and `needs_recovery` clear (or `s_state` valid on a volume with no journal). The flusher marks an idle mount at rest, and the next change marks it in use first | A cleanly unmounted or frozen (`fsfreeze`) ext4 volume on Linux | [Crash recovery](/docs/architecture/crash-recovery#what-happens-at-the-next-boot) |
| Attested program | What the kernel records a process as running: a base program, a package's program, or *other*. It lapses when the process `exec`s, maps code from elsewhere executable or exits | | [Privileged actions](/docs/architecture/privd#how-privd-knows-who-is-asking) |
| Base | The read-only userland image: `/bin`, `/sbin`, `/lib`, `/usr/bin`, `/usr/share` and `/etc/ssl`, packed as one archive and mounted over the root at boot | The read-only `/usr` of an image-based system | [Base system](/docs/architecture/base) |
| Base interface | The number naming the private call surface a base was built against. A kernel serves a range of them and boots only a base inside it | | [Base system](/docs/architecture/base), [Interfaces and stability](/docs/abi/interfaces) |
| Boot partition | The FAT32 partition holding the kernel slots and the two bases, `current` and `previous` | `/boot` | [Updating SlopOS](/docs/self-hosting/updating) |
| Broker | The program on the developer's host (`scripts/remote.py serve`) that a paired machine dials and that hands it commands | | [Remote control](/docs/self-hosting/remote-control) |
| Buffer serial | The number a program gives each pair of window buffers, one higher after every resize. An attach names a buffer by slot and serial and the compositor's release repeats both, so a release for a replaced buffer frees nothing of its successor | No Wayland equivalent; a `wl_buffer` is an object of its own | [Windowing](/docs/architecture/userland-windowing), [Window protocol](/docs/abi/window-protocol#buffers) |
| Capability | A named power, such as `Power` or `Mount`, held as one bit of a process's capability mask. A uid grants none | A Linux capability (`CAP_SYS_BOOT`) | [Capabilities](/docs/architecture/authority) |
| Ceiling | The most a grant may include: the base's list for packages, a signing key's list, or `REQUESTER_CEILING` for an action that runs as the person who asked, as `priv` does | A bounding set | [Packages](/docs/architecture/packages), [Privileged actions](/docs/architecture/privd) |
| Claim | A block device's record of who is using it: a write claim is exclusive, read claims share. Mounts and raw writes take one | Exclusive open of a block device | [Disks](/docs/architecture/storage) |
| Commit (a slot) | Making the kernel that booted this time the default, after a one-shot boot proved it | Marking a boot entry good | [Updating SlopOS](/docs/self-hosting/updating) |
| Commit ceiling | The most private memory the kernel will promise to programs at once, by default all usable RAM. A request that would pass it is refused with `ENOMEM` | Linux's strict overcommit limit (`CommitLimit`) | [Resource limits](/docs/architecture/resource-accounting#why-slopos-refuses-memory-up-front) |
| Commit class | How one memory region is charged against the commit ceiling: nothing, its whole span when created, or a page at a time | | [Resource limits](/docs/architecture/resource-accounting#for-contributors) |
| Computer's layout | The keyboard layout named in `/etc/keymap`, used on the login screen, on the console and by everyone who chose none of their own | The system keymap (`/etc/vconsole.conf`) | [Drivers](/docs/architecture/drivers#keyboards-and-pointers) |
| Consent dialog | The question the desktop shows when privd needs a person to allow an action, with a click or a password | A polkit authentication agent, UAC prompt | [Privileged actions](/docs/architecture/privd), [Desktop](/docs/architecture/desktop) |
| Crash partition | A small partition on the boot disk where a panicking kernel writes a crash record | pstore backend | [Diagnosing the kernel](/docs/development/diagnostics) |
| Crash record | The panic report and the tail of the kernel log, written to the crash partition as the kernel dies and copied to `/var/log/crash/` at the next boot | A pstore or ramoops record | [Diagnosing the kernel](/docs/development/diagnostics) |
| Credentials | A process's real, effective and saved uid and gid and its supplementary groups. They say who a process is, never what it may do beyond file permissions and whom it may signal | Linux `struct cred` | [Users and file permissions](/docs/architecture/users) |
| Current, previous | The two bases on the boot partition. Every slot boots current; previous is the one that ran before it, which a kernel that can't serve current boots instead and which `bootctl base rollback` makes current again |  | [Base system](/docs/architecture/base#where-the-base-lives-on-disk) |
| Delegate | To hand a child, when spawning it, some of the capabilities the parent holds. A child never gets more than its parent | | [Capabilities](/docs/architecture/authority) |
| Diagnostic console | Keys pressed on the physical keyboard (Alt+PrintScreen, then a command key) or a serial BREAK that make the kernel print its state | Magic SysRq | [Diagnosing the kernel](/docs/development/diagnostics) |
| Drain | What privd does on `SIGTERM` before a new base's privd replaces it: stop listening, refuse new requests, start no mechanism and exit once every request it took is answered | A graceful shutdown | [Privileged actions](/docs/architecture/privd#when-a-new-base-replaces-privd) |
| Engine (the installer's) | The part of `/bin/installer` that reads the disks, proposes an install and carries it out, reporting everything as events and printing nothing. privd runs it; the window and the terminal installer only show what it reports. | Subiquity's server | [Installing SlopOS](/docs/self-hosting/installing#for-contributors) |
| Existence reference | The one reference every task holds to itself from the moment it is entered in the task table until it is reaped | Linux's base reference on a `task_struct` | [Task lifetimes](/docs/architecture/task-ownership#why-each-task-holds-a-reference-to-itself) |
| Explicit test | A test that ends the machine or needs the host to act, so it runs only when a `tests.run` pattern is its full name, never through a wildcard | | [Write tests](/docs/development/adding-tests#1-write-a-kernel-test) |
| First person | The person with uid 1000, named `user` unless the installer was told otherwise. They hold the workspace at `/src` and cannot be removed | The first user an installer creates | [Users and file permissions](/docs/architecture/users) |
| First user (of a package) | The user a package's first `user` line declares. It owns the package's log, state and runtime directories, and the mechanisms of the package's actions run as it. Not the first person | | [Package images](/docs/abi/package-images#declarations) |
| Fixture | Setup a test phase shares, registered with `fixture!`: it runs before the phase's first test whenever the phase runs any, whatever the filter, is not counted as a test, and ends the phase when it fails | A pytest session fixture | [Write tests](/docs/development/adding-tests#1-write-a-kernel-test) |
| Frame pacing | Holding a program's next frame back until the compositor says the last one reached the screen (`FrameDone`), so a program draws once for each frame shown | Wayland frame callbacks | [Windowing](/docs/architecture/userland-windowing#frame-pacing) |
| Framekernel | A kernel in which one trusted crate holds every line of `unsafe` code and all others are forbidden it | (Asterinas's term) | [The framekernel](/docs/verification/framekernel) |
| Function (of a USB device) | The part of a USB device one driver binds: an interface, or the interfaces the device declares belong together | A USB interface, which is what a Linux driver binds | [USB](/docs/architecture/usb#how-a-device-reaches-a-driver) |
| Gate | A check that fails the build when the source tree, the linked kernel, the built userland or a test boot breaks a rule. Source and image gates are modules of `tools/xtask`, log gates of the test runner, toolchain gates scripts | A lint or CI check | [Safety gates](/docs/verification/tcb-discipline) |
| Gated capability | Any capability except the two universal ones; holding one makes a program start in secure mode | | [Capabilities](/docs/architecture/authority) |
| Generation | One base as served while the system runs. The base booted is generation 1; each live replacement is the next. Also one numbered copy of a sealed store's file (the accounts record, a package's record, the trusted keys), of which the newest sealed one is believed | | [Base system](/docs/architecture/base), [Users and file permissions](/docs/architecture/users#the-accounts-record) |
| Grant | What a package may hold and do: capabilities, actions people reach unasked, users and commands. A person approves it at a first install; a signed install takes it unasked within the signing key's ceilings | | [Packages](/docs/architecture/packages) |
| Graveyard | The list of dead tasks whose last reference was given back where they could not be freed; a CPU frees them at its next safe moment | Linux's deferred `put_task_struct` | [Task lifetimes](/docs/architecture/task-ownership#when-a-task-cant-be-freed-immediately) |
| Greeter | The login screen, run by the compositor as the base's `greeter` user (uid 50) | A display manager's greeter | [Sessions and login](/docs/architecture/sessions) |
| Host tree | A directory the host copies into a root image on the host and keeps owning, recording what it copied in a manifest beside the image (never in the guest) and, when its build changes, replacing exactly that. The images a development or self-hosting root is offered reach `/var/lib/slopos/offered` this way | | [Development machine](/docs/self-hosting/development-machine#host-trees-and-seed-trees) |
| In front, behind | Whether a graphical session holds the screen and the input now. A desktop behind is locked | Active and inactive sessions | [Sessions and login](/docs/architecture/sessions) |
| Ink and fill | The two colours of each status hue: a light ink for text on a surface, and a deep fill that white text sits on, as in a filled button | None | [Desktop](/docs/architecture/desktop#the-theme) |
| Input sink | The one place key and pointer events go: the program that holds it, the compositor of the session in front, gets every event, and while nothing holds it keys go to the console | | [Drivers](/docs/architecture/drivers#keyboards-and-pointers) |
| Install medium | The live ISO, on a CD or a USB stick, that boots SlopOS from RAM and carries the installer | Installation media | [Installing SlopOS](/docs/self-hosting/installing) |
| Kept answer | An answer privd remembers for an action's `keep` seconds, so the same request from the same shell runs unasked | sudo's timestamp, polkit's `_keep` results | [Privileged actions](/docs/architecture/privd#kept-answers) |
| Kept directory | A directory the kernel holds in place once the root and the `mount=` volumes are up (`/etc`, `/var/lib/slopos` and the stores under it): it cannot be renamed or removed, nothing may be mounted at, above or beneath it, and the volume holding it cannot be unmounted | | [Filesystem](/docs/architecture/filesystem#directories-the-kernel-keeps-in-place) |
| Kept network settings | What `/etc/network` holds and `netctl` changes: whether networking is on, the DNS servers, and per adapter `auto`, a manual address or `off`. Init applies them at every start and as each adapter appears; `ip` changes last only until the next start | systemd-networkd's `.network` files | [Networking](/docs/architecture/networking#settings-that-last-across-restarts) |
| Kernel variant | One of the four kernel builds, `dev`, `release`, `tests` and `release-tests`, each written to its own `builddir/kernel-<variant>.elf` and graded against its own allowlists | A build configuration | [Safety gates](/docs/verification/tcb-discipline#kernel-image-gates) |
| Keyboard state | The kernel's single record of held keys, modifiers, locks and the layout, which every keyboard feeds | Linux merges keyboards only for its text console | [Drivers](/docs/architecture/drivers#keyboards-and-pointers) |
| Keyline | The guide rectangle an app icon's glyph must fill and stay inside (landscape, portrait or square, all of about one area), so no icon looks bigger than another | Keyline shapes in Material's and Apple's icon grids | [Desktop](/docs/architecture/desktop#app-icons) |
| Kill flag | The mark that ends a task: it is set and the task woken, and the task then unwinds and exits from its own context | | [Scheduling and waiting](/docs/architecture/scheduler-wait-protocol#killing-a-task-that-is-waiting) |
| KTAP | The line format the test harness prints results in | (Linux's kernel test format) | [Test output format](/docs/abi/ktap-test-output) |
| Lane | One of the `just ci-*` recipes, which is everything one CI job runs after the shared setup | A CI job | [Write tests](/docs/development/adding-tests#what-ci-runs) |
| Layout audit | appkit's check that lays a view out off screen at several widths and reports cut text, overlaps, mismatched baselines, hidden focus, small controls and low contrast | None; nearest is an accessibility linter run on rendered output | [Desktop](/docs/architecture/desktop#how-the-look-is-checked) |
| Level | How much privd asks of a person before it runs an action for them: nothing, `confirm` (a click at their own desktop, their password elsewhere), `password` (their own password) or `alone` (for `user`: nothing for an administrator or while nobody else is logged in, and otherwise an administrator's password; for `greeter`: nothing while nobody is logged in, and otherwise refused) | polkit's `yes`, `auth_self`, `auth_admin` | [Privileged actions](/docs/architecture/privd#who-may-ask-and-what-they-must-do) |
| Live boot | A boot from the install medium onto a root in RAM, so nothing done there is saved. Its desktop opens the installer's welcome page | A live CD session | [Installing SlopOS](/docs/self-hosting/installing#starting-the-computer-from-it) |
| Lock screen | What a desktop shows while it is locked: the time, the person's name and a field for their password. The desktop's own compositor draws it | A screen locker | [Sessions and login](/docs/architecture/sessions#locking-and-unlocking) |
| Log gate | A check, `run_tests gate <name>`, that grades the saved serial output of a test boot against a tracked file under `scripts/gates/` without booting anything | | [Test output format](/docs/abi/ktap-test-output#log-gates) |
| Login screen | The screen that lists the people and asks the chosen one for their password, shown at boot when nobody is logged in automatically, on *Switch user…* and after logging out. The compositor runs it as the `greeter` user | A display manager's login screen | [Sessions and login](/docs/architecture/sessions#logging-in-at-the-login-screen) |
| Login tag | A number every process carries and passes to its children, naming the session, or the system service, it belongs to. Only a `SetId` holder gives a new process another one | Linux's audit session id | [Sessions and login](/docs/architecture/sessions#login-tags) |
| Manifest | The list of what a base or a package image holds, which an install, an update or a replacement reads to know what is there. Both carry theirs inside them | | [Base system](/docs/architecture/base), [Package images](/docs/abi/package-images#packagemanifest) |
| Materialised tree | A pinned upstream source tree (the standard library sysroot, the rustc sources, llvm-project, the vendored crates) unpacked under `third_party/` with the SlopOS patches applied. It is not tracked; it carries a stamp, a digest of the pins and patches it was built from, which the toolchain gates compare with what those hash to now | A patched vendor checkout | [Toolchain gates](/docs/verification/toolchain-gates#conventions), [The toolchain](/docs/self-hosting/toolchain) |
| Mechanism | The program privd starts to carry out an action, with the action's capabilities | A polkit mechanism | [Privileged actions](/docs/architecture/privd) |
| net-timer | The kernel thread that runs the network protocols' timers and samples every card's link state | Linux's timer softirq and link watch | [Networking](/docs/architecture/networking#how-a-packet-reaches-your-program) |
| netpoll | The one kernel thread that collects received packets from every card in bounded batches, woken by the cards' interrupts | A NAPI poll in softirq context | [Networking](/docs/architecture/networking#how-a-packet-reaches-your-program) |
| Number (of a package) | The uid its record gives the package's own name, kept for good, taken only by a package whose images grant a user. Init makes the login tags of its services and mechanisms from it, and of two packages that want one socket the higher number runs no service | | [Packages](/docs/architecture/packages#for-contributors) |
| One-time boot | A boot of a named entry that the loader takes once and then forgets (`LoaderEntryOneShot`), which is how a new kernel is tried before it is committed. | FreeBSD `nextboot`, `BootNext`, systemd-boot's one-shot entry | [Updating SlopOS](/docs/self-hosting/updating#installing-trying-and-committing) |
| Offered image | An image and its sidecar that uid 0 left in `/var/lib/slopos/offered` (on a live boot, the medium's `images/`). Init installs each at boot with nobody asked, if it declares no user, service, action or directory, is signed by nobody and is above the version floor | A distribution's preinstalled package | [Packages](/docs/architecture/packages) |
| OSTD | `slopos-ostd`, the one kernel crate allowed `unsafe`. SlopOS reads the name as Operating System Trusted Domain; Asterinas, where it comes from, as Operating System Standard Library | | [The trusted core](/docs/verification/ostd-trusted-core) |
| Owned sysroot | SlopOS's own copy of the pinned Rust toolchain (`third_party/rust-slopos`, registered as `slopos`), whose standard library sources carry the std and libc forks | A rustup toolchain | [Toolchain](/docs/self-hosting/toolchain#the-owned-sysroot) |
| Owners record | The file `/var/lib/slopos/owners`, one `<uid>:<gid> <tree>` line for each tree the first person holds, their home and `/src`; a line naming any other tree is ignored. A root whose record is absent or unreadable gives the first person nothing | No direct equivalent | [Users and file permissions](/docs/architecture/users#who-owns-what-on-a-disk) |
| Ownership map | The one statement of which directories every root has, who owns each and with what mode (`ROOT_LAYOUT` and `PERSON_TREES`). The image builders, the installer and init all lay a root out by it, and a host check holds a disk image to it | The Filesystem Hierarchy Standard plus a distribution's `tmpfiles.d` | [Users and file permissions](/docs/architecture/users#who-owns-what-on-a-disk) |
| Package | One piece of software outside the base, installed as a signed or approved image and shown read-only at `/opt/<name>`: an app, the toolchain, a service. Its services run as users of its own, its powers are its grant, and it keeps its previous image to go back to. No package depends on another | An Android package; what the Filesystem Hierarchy Standard puts at `/opt/<package>`. Not a distribution's package, which has dependencies and unpacks into shared directories | [Packages](/docs/architecture/packages) |
| Paired agent | `remoted` on a machine whose base carries a pairing with a broker. privd's `paired` principal | | [Remote control](/docs/self-hosting/remote-control) |
| Pairing | The broker's address, certificate authority and token, packed into a base at `/usr/share/slopos/remote/`. `remoted` dials the broker it names and reads it from nowhere else, so no program can point the agent at another broker | | [Remote control](/docs/self-hosting/remote-control) |
| Payload | The partition on an install medium that holds the toolchain image and the source, installed alongside SlopOS | | [Installing SlopOS](/docs/self-hosting/installing) |
| Pending (control) | A control whose change the system has yet to make: it shows what was asked and stays a control, never disabled. `appkit::Pending` holds what was asked, answered in the order asked | GtkSwitch's `active` ahead of its `state` | [Desktop](/docs/architecture/desktop#components) |
| Per-build set | The image gates that run after every kernel build: `stack-sizes`, `softfloat`, `registry-sections` and `stack-rewind` | | [Safety gates](/docs/verification/tcb-discipline#kernel-image-gates) |
| Person | A human with an account in the accounts record, uid 1000 to 59999 | A regular user | [Users and file permissions](/docs/architecture/users) |
| Pin | A `PIN` file under `toolchain/` naming the exact upstream version and the checksum of each patch applied to it; a gate fails when the tree on disk differs | A lockfile | [Toolchain](/docs/self-hosting/toolchain#the-owned-sysroot) |
| Pinned mount | A mount that `umount` refuses and under which nothing else may be mounted, as the base's directories are | | [Base system](/docs/architecture/base#how-the-base-appears-in-the-file-tree), [Filesystem](/docs/architecture/filesystem) |
| Preferences | What belongs to one person rather than the computer: their keyboard layout, background and clock format, kept as `key = value` lines in `~/.config/slopos/prefs` and changed by Settings, `/bin/prefs` or an editor | dconf or GSettings user settings | [Settings and preferences](/docs/architecture/settings#each-persons-preferences) |
| Principal | Who an `allow` line in privd's policy names: `root`, `user`, `admin`, `greeter`, `paired` or a `program` | polkit's subject | [Privileged actions](/docs/architecture/privd) |
| privd | The privilege broker: the service that runs actions on behalf of programs that may not do them, asking the person first when the policy says so | polkitd | [Privileged actions](/docs/architecture/privd) |
| Proposal | What the installer's engine says a set of choices would do to a disk: the disk before and after, and an action for each partition. The engine installs only the proposal it made last, after reading the disk again. | An installer's review page, a partitioning plan | [Installing SlopOS](/docs/self-hosting/installing#what-the-installer-writes-and-what-it-never-writes) |
| Quarantine | Where the request engine keeps a timed-out request's pages and tag until the device hands the request back, so a late completion can't write into reused memory | None direct; Linux aborts the command or resets the controller | [Disks](/docs/architecture/storage#when-a-disk-stops-answering) |
| Ratchet | A gate whose tracked file holds measured values (a test list, a peak, a cost per MiB): a change that moves one regenerates the file with `--emit-allowlist` in the same commit and never edits it by hand | | [Write tests](/docs/development/adding-tests#when-a-gate-fails-after-a-real-change) |
| Recipe | A file under `toolchain/recipes/` that pins a third-party project's tarball, checksum, licence and build template, built for SlopOS | A Redox cookbook recipe, a port | [Toolchain](/docs/self-hosting/toolchain#third-party-programs) |
| Registry | A table the linker assembles from entries spread across crates (boot steps, drivers, tests), which OSTD reads back as a slice at run time | A linker set | [Unsafe code and FFI](/docs/development/unsafe-ffi-boundaries#add-an-entry-to-a-linker-table) |
| Request engine | The part of the block layer every disk shares: request slots with preallocated pages, retry, timeout, quarantine and the write fence. A transport supplies only the queue operations | Linux's blk-mq core under a driver | [Disks](/docs/architecture/storage#how-a-request-reaches-the-disk) |
| Requester | The program that asks privd for an action | polkit's subject process | [Privileged actions](/docs/architecture/privd) |
| Requester ceiling | The six capabilities an action run as its requester may hold at most, which is what `priv` gives | | [Privileged actions](/docs/architecture/privd#running-a-command-with-priv) |
| Rescue shell | A shell holding every delegable capability, started from the install medium to repair an installed system | A recovery shell | [Installing SlopOS](/docs/self-hosting/installing) |
| Retired uid | A uid of a removed package that is not given back yet, because something it owns is left or a task still runs as it. The record keeps it `retired`, and a later `pkgctl remove` tries again to free it | | [Packages](/docs/architecture/packages) |
| Role (theme) | A named design value an app asks for in place of a number: a surface, a tone, a text role, a spacing step. `theme-core` holds the one table that gives each its colour or size | A design token; libadwaita's named colours | [Desktop](/docs/architecture/desktop#the-theme) |
| Safety gate | A script that fails the build or CI when the source tree, the compiled kernel, the built userland or a test run breaks one of the tree's rules, such as `unsafe` code outside the trusted core or a kernel stack frame over 2 KiB |  | [Safety gates](/docs/verification/tcb-discipline), [Interfaces and stability](/docs/abi/interfaces) |
| Seal | A file or directory marked immutable, which only a `Seal` holder can mark or unmark. Every file of the base is sealed | The immutable attribute (`chattr +i`) | [Filesystem](/docs/architecture/filesystem#sealed-files) |
| Seat | Either of the two things one process holds at a time: the screen, or the stream of input events. Init hands both from session to session | A logind seat | [Sessions and login](/docs/architecture/sessions#how-the-seat-moves-between-sessions), [Windowing](/docs/architecture/userland-windowing) |
| Secure mode | How a program starts when it holds a gated capability, runs with ids other than its starter's real ones, or is a package's program, whoever starts it (`AT_SECURE`): the loader ignores `LD_LIBRARY_PATH` and `$ORIGIN` and searches no library directory a person can write | Linux's secure-execution mode for setuid programs | [Capabilities](/docs/architecture/authority#how-a-process-gets-its-capabilities), [Processes and signals](/docs/architecture/processes#replacing-the-program-exec) |
| Seed tree | A directory the host copies only onto a root image that lacks it and that is the guest's from then on, such as the clone at `/src/slopos` | | [Development machine](/docs/self-hosting/development-machine#host-trees-and-seed-trees) |
