This page lists every option the kernel reads from its command line: first the
three whose names Linux also uses, then the ones only SlopOS has, grouped by
what they control. The parsers are authoritative: `boot/src/early_init.rs`
(most options), `boot/src/boot_drivers.rs` (display and input),
`boot/src/boot_services.rs` (`root=` and `mount=` at boot),
`ktesting/src/config.rs` (`tests.*`), `slopos-ostd/src/kconsole/config.rs`
(`kconsole.*`), `cpufreq-core/src/config.rs` (`cpufreq.*`, `sched.hybrid`),
`usb-core/src/knob.rs` (`usb.*`) and `drivers/src/xe_logic/cmdline.rs`
(`xe.*`). The command line itself is assembled in
`boot/src/limine_protocol.rs`.

## How to pass options

The command line is a list of options separated by spaces. The boot loader
(Limine) hands it to the kernel from its configuration, which the build
scripts write when they build an image, so changing it means rebuilding the
image.

| How you boot | Command line |
|---|---|
| `just iso`, `just boot-live`, `just boot-log` (live ISO) | `BOOT_CMDLINE`, default `tests=off root=initramfs`, plus `boot.debug=on` with `DEBUG=1` and `roulette=skip` with `ROULETTE=0` |
| `just boot`, `just boot-fast`, `just boot-debug` (development boot disk) | `tests=off`, plus the same `DEBUG` and `ROULETTE` additions; each slot's entry adds `slot=<name>`, which the kernel does not read |
| `just test` and its variants | The justfile's `test_cmdline`: `tests=on tests.shutdown=on tests.verbosity=summary boot.debug=on roulette=skip root=auto mount=LABEL=slopos-media:/media`, plus the `tests.*` options the runner adds from its flags, `tests.warn_ms=500` among them by default (see [Test output format](/docs/abi/ktap-test-output#host-runner)). The runner rebuilds the line from `test_cmdline` on every run, so `TEST_CMDLINE` in the environment does not reach it. `just test-userland-only` and `just test-elf` boot `TEST_CMDLINE` from the environment when it is set, `test_cmdline` otherwise; `test-userland-only` adds `tests.run=__userland_only__`, which matches no test in either phase, so only the `tests.run=` patterns `TEST_CMDLINE` carries run, and `test-elf` adds a `tests.run=` for the glob it is given |
| `just test-persist`, `test-rude-exit`, `test-capacity`, `test-install` | `test_cmdline` and a `tests.run=` naming their tests; `test-install`'s slots boot with `root=PARTUUID=` of the disk's root partition in place of `root=auto` |
| `just test-usb` | `tests=on tests.shutdown=on tests.verbosity=summary boot.debug=on roulette=skip root=initramfs` and a `tests.run=` naming the USB tests |
| `just test-installer` | The live ISO: `tests=on tests.shutdown=on tests.verbosity=summary boot.debug=off roulette=skip root=initramfs watchdog.miss_threshold=300 tests.run=*ext4_aaa*,*installer*`. The systems it installs are given the same words through `installer --cmdline`, with `panic=reboot` in place of `root=initramfs` |
| `just test-remote` | `tests=off roulette=skip`, its slots with `root=PARTUUID=` of the disk's root partition |
| `just test-toolchain`, `test-selfhost`, `bench-selfhost`, `test-install-guest` | `test_cmdline` with `boot.debug=off`, plus `watchdog.miss_threshold=300` and a `tests.run=` naming their tests. All but `test-install-guest` append `TEST_CMDLINE_EXTRA`; `bench-selfhost` also adds `prof=on` unless `BENCH_PROF` is set |
| An installed system | `root=PARTUUID=<root partition> panic=reboot`, where `installer --cmdline <words>` replaces `panic=reboot` |

```sh
BOOT_CMDLINE='tests=off root=initramfs lockdep=warn' just boot-live
just test 'slopos_mm::*'    # tests=on ... tests.run=slopos_mm::*
```

### Built-in command line

A kernel built with `SLOPOS_BUILTIN_CMDLINE` set carries that text and
appends it to the loader's command line, so an option read by its last
occurrence takes the built-in value. This is how a kernel installed into a
slot whose loader entry is fixed still boots with an experiment's options:

```sh
SLOPOS_BUILTIN_CMDLINE='cpufreq=firmware prof=on' just remote-install
```

The boot log says `BOOT: built-in command line appended: <text>`. The two lines,
with a space between them, must together be shorter than 1024 bytes; when they
are not, the kernel uses the loader's alone and logs
`BOOT: built-in command line dropped: it does not fit beside the loader's`.

## How options are read

- An option the kernel does not know is ignored.
- A known option with a value it does not accept is ignored, and the option
  keeps the value it had. Most such options log a `Boot option:` line naming what they
  accept; an on/off option logs
  `Boot option: <key>=<value> ignored (want on or off)`.
- On/off options accept exactly `on` and `off`.
- Where an option appears more than once, the last accepted value wins.
  The exceptions: `mount=`, `tests.run=` and `tests.skip=` accumulate;
  `prof=on`, `panic=reboot` and `verity=require` take effect wherever they
  appear;
  `extensions=off` takes effect wherever it appears, and a later
  `extensions=on` does not undo it.
- `video=framebuffer`, `roulette=skip`, `tp.off`, `tp.poll`, `tp.debug`,
  `platform.debug`, `panic.post_boot_unwind=on`, `panic.fatal_smoke=on` and
  `panic.nested_drop_smoke=on` are matched as text
  anywhere in the line, and the userland test mode is set by any `tests=on`.

## Names Linux also uses

Three options share a name with a Linux kernel parameter. Each entry says how
it differs from Linux's.

### `root=`

- **Values:** `auto`, `initramfs`, `disk`, or a device. Only the last
  `root=` on the line is read.
- **Default:** `auto`.
- **Effect:** chooses what `/` is.
  - `auto` mounts the first disk that is not a USB disk (`nvme0n1` under
    QEMU) at `/` if it mounts writable. If there is no such disk, or it
    mounts read-only, `/` is the initramfs (the base archive unpacked into
    memory), and a disk that mounted read-only is shown at `/mnt`.
  - `initramfs` uses the initramfs and attaches no root disk. It still
    mounts what a `mount=` names and an install medium's payload.
  - `disk` requires the disk as `/`, read-only or not, and fails the boot
    without one.
  - A device is named in any spelling `mount(2)` accepts: a node name
    (`nvme0n1p2`), its `/dev/` path, `PARTUUID=`, `UUID=` (both
    case-insensitive), `LABEL=`, or a path under `/dev/disk/by-id/`,
    `by-label/`, `by-partuuid/` or `by-uuid/`. A partition comes from the GPT
    or MBR table on its disk. A named device that is absent is waited for
    until USB settles (at most `usb.settle_ms`). If it is still absent, the
    boot logs `FS: root=<device> names no usable block device (...)` and
    uses the initramfs, as it does when the device holds no volume the
    kernel can mount. A named device that mounts read-only is treated as
    `auto` treats the first disk: `/` is the initramfs and the device is
    shown at `/mnt`.
- **Differs from Linux:** Linux's `root=` takes a block device (`/dev/<name>`,
  `PARTUUID=`, `PARTLABEL=` or a hexadecimal device number) or `ram`, `nfs`,
  `cifs`, `mtd` or `ubi`, and leaves a filesystem's `UUID=` or `LABEL=` to an
  initramfs. SlopOS resolves `UUID=`, `LABEL=` and the `/dev/disk/by-*` paths
  itself, has the three modes above, and takes neither `PARTLABEL=` nor a
  device number. Instead of Linux's `rootwait` and `rootdelay=`, an absent
  device is waited for as above.

[Disks](/docs/architecture/storage) and [Filesystem](/docs/architecture/filesystem)
explain how the root is chosen and mounted.

### `panic=`

- **Values:** `reboot`.
- **Default:** halt.
- **Effect:** a kernel panic resets the machine (through ACPI, then port
  `0xCF9`, then the keyboard controller) instead of halting it. The crash
  record is written first. On bare metal the panic screen stays up for ten
  seconds before the reset; under a hypervisor the reset is immediate. The
  format-free abort a lockup takes resets by a triple fault. An installed
  system boots with this, so that a slot whose kernel panics falls back to
  the loader's default entry.
- **Differs from Linux:** Linux's `panic=<timeout>` takes a number of seconds
  (`0` waits forever, a negative value reboots at once). SlopOS reads only
  `panic=reboot`; a number is ignored without a log line.

### `video=`

- **Values:** `framebuffer`.
- **Default:** a GPU driver takes the display when it binds.
- **Effect:** ranks the firmware framebuffer above every GPU driver, so it
  stays the display.
- **Differs from Linux:** Linux's `video=` configures a framebuffer driver's
  mode. SlopOS reads only `video=framebuffer`, which Linux does not define.

## Options only SlopOS has

The rest of the options have no Linux counterpart of the same name.

### Root filesystem and mounts

| Option | Values | Default | Effect |
|---|---|---|---|
| `mount=` | `<source>:/<path>`, repeatable | none | Once the root is up, mounts the ext2/3/4 volume `<source>` at `/<path>`, read-write, in command-line order, so a later entry may mount inside an earlier one. The value splits at its first `:/`, so a `LABEL=` may hold a colon. `<source>` takes every spelling `root=` takes; an absent one is waited for as for `root=`. The target is refused as `mount(2)` refuses it: `/` itself, anything at or beneath a base directory, and anything at, above or beneath a directory the kernel keeps (`/etc` and `/var/lib/slopos`, so `/var` and `/var/lib` too). Each logs `MOUNT: <source> at <path> (ext4, read-write)` (or `read-only`); a failure logs `MOUNT: mount=<value> failed (...); continuing` and the boot goes on |
| `verity=` | `require` | off | The root disk must mount with a verity trailer (a table of each block's CRC-32 appended to the image, which the kernel checks every block it reads against), or the `fs init` boot step fails. A boot with no disk at all still passes |

### Boot and userland

| Option | Values | Default | Effect |
|---|---|---|---|
| `roulette=skip` | `skip` | spin | init does not run `/bin/roulette`, the Wheel of Fate, at startup |
| `extensions=` | `on`, `off` | `on` | `off` activates no extension this boot: init does not run `extctl activate-all`, `ext_activate` answers `EPERM`, and `sys_info` reports `BOOT_FLAG_EXTENSIONS_OFF`. See [Extensions](/docs/architecture/extensions) |

### Hardware

| Option | Values | Default | Effect |
|---|---|---|---|
| `usb=` | `on`, `off`, `report` | `on` | `on` takes every xHCI controller the kernel can drive from the firmware and runs it. `off` binds none and touches nothing. `report` logs each controller's capabilities, protocols and ports and leaves it to the firmware. Any other value logs `USB: usb=<value> names no mode; ignored`. See [USB](/docs/architecture/usb) |
| `usb.settle_ms=` | milliseconds | `5000` | How long a USB disk's LUN may stay not ready at probe, and how long the boot waits for USB to settle when the device `root=` or a `mount=` names is absent, or before an install medium looks for its payload |
| `serial_mirror=off` | `off` | mirroring on | Stops copying the text console's output to the serial port |
| `tp.off` | flag | off | Skips the Intel LPSS I²C controllers and the I²C-HID touchpad behind them |
| `tp.poll` | flag | off | Drives the touchpad by polling instead of interrupts |
| `tp.debug` | flag | off | Verbose touchpad bring-up logging, and a periodic check for sleeping tasks that missed their wake-up |
| `platform.debug` | flag | off | Verbose logging while the kernel searches the ACPI tables for platform devices (the PS/2 controller, the touchpad) |

#### Intel GPU (`xe`)

Recovery and expert overrides for the Intel Xe display driver. A value it
does not accept is ignored without a log line.

| Option | Values | Default | Effect |
|---|---|---|---|
| `xe.modeset=` | `on`, `off` | `on` | `off` leaves the firmware framebuffer in place and touches no display register |
| `xe.diag=` | `on`, `off` | `off` | Logs decoded display registers (`XE-DIAG:` lines) while probing |
| `xe.nocursor=` | `on`, `off` | `off` | Skips the hardware cursor plane; the compositor draws the cursor itself |
| `xe.pipe=` | `A`, `B`, `C` (either case) | detected | Forces which display pipe is treated as the active one |
| `xe.wdog_ms=` | decimal milliseconds | `100` | How long the driver checks that the display is still scanning after switching it over, before it rolls back to the firmware framebuffer. Never less than 20 |
| `xe.force_did=` | hexadecimal with `0x` | the device's own ID | Treats the GPU as this PCI device ID, for hardware not yet in the driver's table |

### CPU and scheduling

| Option | Values | Default | Effect |
|---|---|---|---|
| `cpufreq=` | `hwp`, `firmware` | `hwp` | `hwp` enables HWP (hardware-managed P-states) on every CPU that has it and asks for autonomous selection between the CPU's lowest and highest level. `firmware` writes no frequency register. A CPU without HWP keeps the firmware's settings either way. See [CPU frequency](/docs/architecture/cpu-frequency) |
| `cpufreq.epp=` | `performance`, `balance_performance`, `balance_power`, `power`, or `0` to `255` (decimal, or hexadecimal with `0x`) | `balance_performance` (128) | The energy-performance preference HWP is given. The names are 0, 128, 192 and 255 |
| `sched.hybrid=` | `on`, `off` | `on` | `on` places a waking or new task on the best idle CPU by class on a machine whose CPUs differ: a P-core with nothing on it, then an E-core, then a busy core's sibling thread. `off` treats every idle CPU alike |
| `sched.ap_pause_ms=` | milliseconds | `12` | How long the kernel waits for the other CPUs to pause when it needs all of them stopped. `0` removes the time limit and falls back to a fixed number of attempts. The default is measured (`AP_PAUSE_BUDGET_NS_DEFAULT` in `sched/src/per_cpu.rs`) |

### Memory and resource limits

| Option | Values | Default | Effect |
|---|---|---|---|
| `mem.commit=` | percent | `100` | How much memory, as a percentage of usable physical memory, the kernel may promise to private mappings. Values above `400` are capped at `400`; `0` counts promises but sets no ceiling. See [Memory](/docs/architecture/memory) |
| `quota=` | `off`, `warn`, `enforce` | `enforce` | What a resource limit does when a program would exceed it. `enforce` refuses the charge; `warn` grants it and counts it as a denial; `off` consults no limit but still counts what each account holds. See [Resource limits](/docs/architecture/resource-accounting) |

### Logging, diagnostics and profiling

| Option | Values | Default | Effect |
|---|---|---|---|
| `boot.debug=` | `on`, `off` | `off` | Sets the kernel log level to debug (`on`) or info (`off`) |
| `prof=` | `on` | off | Samples where the time goes: each CPU's user, kernel, idle and halted time, its busy share and effective clock, the hottest kernel addresses, user time by task name, and the kernel stacks blocked user tasks wait on. A test run prints the report as `PROF[post-userland-tests]:` lines; on a running system `/bin/prof` starts, stops and reports the same profiler |
| `kconsole=` | `on`, `off`, or a hexadecimal mask (`0x` optional) | `on` | Which classes of [diagnostic console](/docs/development/diagnostics) commands may run. `on` is the informational commands only (mask `0x1`); `0x3` adds the commands that take the machine down (`0x2`); `off` disables the console |
| `kconsole.serial=` | `on`, `off` | `on` | Whether a serial BREAK arms the diagnostic console |
| `kconsole.arm_ms=` | `0` to `65535` | `3000` | How long, in milliseconds, the console waits for a command key after it is armed |
| `kconsole.max_lines=` | `0` to `65535` | `512` | The most lines one command may print |
| `kconsole.probe_ms=` | `0` to `65535` | `250` | How long, in milliseconds, the all-CPU probe waits for each CPU to answer |
| `lockdep=` | `off`, `warn`, `panic` | `panic` | What the lock-order checker does when it finds two locks taken in an order that could deadlock. `warn` reports each distinct pair once and keeps booting; `off` skips the ordering checks but still tracks which locks each CPU holds |
| `watchdog=` | `on`, `off` | `on` | Whether the watchdog reports a CPU that has stopped making progress |
| `watchdog.miss_threshold=` | positive integer | `100` | Consecutive heartbeat samples (one per timer tick, so 100 is a second) a CPU may miss before it is reported. `0` is refused |
| `watchdog.panic=` | `on`, `off` | `on` on bare metal, `off` under a hypervisor | Whether a long stall stops the machine: a stall five thresholds long, or one threshold long when the stalled CPUs wait on each other in a cycle, takes the format-free abort (the stuck CPU halts, `=== KERNEL ABORT ===` is printed and a crash record written, with no panic screen; under `panic=reboot` the machine resets at once). A hypervisor can pause a virtual CPU, which looks the same as a stalled one, which is why the default differs |

### Panics

| Option | Values | Default | Effect |
|---|---|---|---|
| `panic.boot=` | `on`, `abort` | off | `on` panics as soon as boot initialisation finishes; `abort` takes the format-free abort a lockup takes instead. `just test-install` builds the broken slots it rolls back from with these |
| `panic.on_oops=` | `on`, `off` | `off` | `on` makes every kernel panic fatal, turning off the recovery of panics in task context |
| `panic.oops_limit=` | integer | `100` | How many panics the kernel may recover from in one boot; the panic that crosses the limit is fatal. `0` removes the limit |
| `panic.recover_smoke=` | `on`, `off` | `off` | Runs the panic-recovery smoke tasks after boot and enables the `test_panic` system call, which otherwise answers `ENOSYS` |
| `panic.post_boot_unwind=on` | `on` | off | Raises a deliberate panic after boot that unwinds; halts the machine |
| `panic.fatal_smoke=on` | `on` | off | Raises a deliberate fatal panic from deep in the call stack; halts the machine |
| `panic.nested_drop_smoke=on` | `on` | off | Raises a panic from a destructor during a recoverable unwind; halts the machine |

The last three check that a panic prints one clean `=== KERNEL PANIC ===`
report. `just test` never sets them.

### Tests

| Option | Values | Default | Effect |
|---|---|---|---|
| `tests=` | `on`, `off` | `off` | Runs the kernel test harness and lets `test_key` answer. It also makes the `usb settle` boot step wait up to a minute for USB to settle and fail the run with `USB: unsettled after 60000 ms` if it does not; on a machine with one CPU and a USB controller the step fails at once. `off` also clears an earlier `tests.shutdown`. Any `tests=on` on the line, whatever follows it, also puts userland in test mode: init runs the userland tests in a copy of itself, and the Wheel of Fate cannot restart the machine |
| `tests.run=` | globs separated by commas | all tests | Runs only tests whose `module::name` matches one of the globs. A test registered as explicit runs only when a pattern is exactly its full name |
| `tests.skip=` | globs separated by commas | none | Skips matching tests |
| `tests.verbosity=` | `quiet`, `summary`, `verbose` (any case) | `summary` | `quiet` prints only failures; `verbose` adds the captured log of passing tests. Any other value means `summary` |
| `tests.warn_ms=` | milliseconds, optional `ms` suffix | `0` (off) | Marks passing tests slower than this as `OVER_TIME` |
| `tests.shutdown=` | `on`, `off` | `off` | Exits QEMU through its `isa-debug-exit` device when the tests finish |

The output these options control is described in
[Test output format](/docs/abi/ktap-test-output).
